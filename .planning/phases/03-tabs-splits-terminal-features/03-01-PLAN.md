<objective>
Refactor the Windows apprt from a single-surface model to a multi-tab architecture with a custom-painted tab bar rendered in the titlebar area.

Purpose: This is the foundation for Phase 3. Currently App.zig owns a single Surface. This plan transforms it to own an ArrayList of Tab structs, each containing a Surface, with a tab bar drawn in the non-client area (titlebar) using custom WM_NCPAINT/DwmExtendFrameIntoClientArea.

Output: Working multi-tab terminal where users can create, close, switch, reorder, and color-code tabs.
</objective>

  <action>
Create Tab.zig containing:
- Tab struct with fields: surface (Surface), title ([:0]const u8 or null), color (optional COLORREF for TAB-06), hwnd (child HWND for the surface content area), active (bool).
- init/deinit lifecycle methods that create a child HWND (WS_CHILD) within the main window's client area for the surface to render into. Each tab's child HWND gets its own WGL context.
- The tab's child HWND is shown/hidden based on whether it is the active tab.

Refactor App.zig:
- Replace `surface: Surface` and `surface_initialized: bool` with `tabs: std.ArrayList(Tab)` and `active_tab: usize`.
- Add `createTab(self: *App) !void` which: allocates a new Tab, creates a child HWND, creates a Surface with its own WGL context on that child HWND, calls core_app.addSurface, shows it if it becomes active tab.
- Add `closeTab(self: *App, index: usize) !void` which: deinits the Surface, destroys the child HWND, removes from tabs list, adjusts active_tab, posts WM_QUIT if no tabs remain.
- Add `switchToTab(self: *App, index: usize) void` which: hides current tab's HWND, shows target tab's HWND, updates active_tab, calls SetFocus on the new tab's HWND.
- Update `performAction` to handle: `.new_tab` (call createTab), `.close_tab` (call closeTab based on CloseTabMode), `.goto_tab` (call switchToTab with GotoTab enum handling previous/next/last/index), `.move_tab` (reorder tabs array by MoveTab.amount, wrapping cyclically).
- Update `.new_window` handler to call createTab instead of the old single-surface init path.
- Update `.set_title` to set title on the active tab (or the target surface's tab).
- Update `.config_change` to apply to all surfaces across all tabs.
- Update WM_SIZE handler to resize only the active tab's child HWND to fill the client area below the tab bar.
- Add WM_LBUTTONDOWN handler in the tab bar region for tab clicking and WM_MBUTTONDOWN for middle-click close.

Refactor Surface.zig:
- Add `tab_index: usize` field so each surface knows which tab it belongs to.
- Change `hwnd` to accept the child HWND from Tab rather than the main window HWND.
- Update close() to notify App to close the containing tab rather than destroying the main window.

CRITICAL: Each tab's Surface needs its own WGL context on its own child HWND (CS_OWNDC). The main window HWND is the frame; child HWNDs are the rendering targets. This matches the pattern where wgl.initContext takes an HWND.

For the tab bar: Use DwmExtendFrameIntoClientArea to extend the frame into the client area by the tab bar height (~30px). Draw tab items in WM_PAINT using GDI (TextOutW for tab titles, FillRect for backgrounds/active indicator, optional colored rectangle for tab color). Handle WM_NCHITTEST to make the extended title bar area draggable (return HTCAPTION) except where tabs are clickable. This gives the "tabs in titlebar" appearance without requiring WinUI 3 TabView.

Win32 extern imports needed: DwmExtendFrameIntoClientArea from dwmapi, CreateWindowExW (for child HWNDs with WS_CHILD style), MoveWindow, ShowWindow with SW_HIDE/SW_SHOW, SetFocus, BeginPaint/EndPaint/FillRect/TextOutW/SetBkMode/SetTextColor from gdi32, WM_PAINT, WM_NCHITTEST, WM_LBUTTONDOWN, WM_MBUTTONDOWN, HTCAPTION.

The MARGINS struct for DwmExtendFrameIntoClientArea: extern struct { cxLeftWidth: i32, cxRightWidth: i32, cyTopHeight: i32, cyBottomHeight: i32 }.
