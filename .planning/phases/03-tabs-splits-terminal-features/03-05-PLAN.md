Three fixes in `translateKeyEvent` in src/apprt/windows/input.zig:

**FIX 1: Filter control characters from utf8 output (lines 93-100)**

After ToUnicode produces text (result > 0), check if the first UTF-16 character is a control character (< 0x20). If so, set utf8_len to 0 (empty text), matching GTK behavior where control characters from IM text are filtered out (see GTK surface.zig lines 1348-1353).

Replace the block at lines 93-100:
```zig
if (result > 0) {
    const first_cp = utf16_buf[0];
    // Filter control characters from ToUnicode output.
    // When Ctrl is held, ToUnicode returns control chars (0x01-0x1F)
    // instead of printable letters. GTK filters these in IM text;
    // we must do the same so key_encode.zig ctrlSeq() receives
    // an empty utf8 and falls back to codepoint-based encoding.
    if (first_cp >= 0x20) {
        const utf16_slice = utf16_buf[0..@intCast(result)];
        utf8_len = std.unicode.utf16LeToUtf8(&utf8_buf, utf16_slice) catch 0;

        // If shift was held and produced text, shift was consumed
        // for text generation (e.g., Shift+a -> "A").
        if (mods.shift) consumed_mods.shift = true;
    }
}
```

**FIX 2: Clear Ctrl and Alt for unshifted_codepoint (lines 105-106)**

The unshifted_codepoint computation currently only clears VK_SHIFT. It must also clear VK_CONTROL and VK_MENU so that ToUnicode returns the base printable character ('c' = 99) instead of a control character (0x03 = 3).

Add two constants near the existing VK constants at the top of the file:
```zig
const VK_CONTROL_U: u8 = 0x11;
const VK_MENU_U: u8 = 0x12; // Alt
```

Replace lines 105-106:
```zig
var unshifted_state = keyboard_state;
unshifted_state[VK_SHIFT_U] = 0; // Clear shift
unshifted_state[VK_CONTROL_U] = 0; // Clear ctrl
unshifted_state[VK_MENU_U] = 0; // Clear alt
```

**FIX 3: Fix dangling pointer for utf8 field (line 76, 129)**

The `utf8_buf` is stack-local. The returned KeyEvent.utf8 slice points to this buffer, which is undefined behavior after the function returns.

Change the declaration at line 76 from:
```zig
var utf8_buf: [16]u8 = undefined;
```
to a threadlocal static:
```zig
const S = struct {
    threadlocal var buf: [16]u8 = undefined;
};
```

Then use `S.buf` everywhere `utf8_buf` was used:
- Line 95: `utf8_len = std.unicode.utf16LeToUtf8(&S.buf, utf16_slice) catch 0;`
- Line 129: `S.buf[0..utf8_len]` instead of `utf8_buf[0..utf8_len]`

This is safe because key events are processed sequentially on the message thread and the KeyEvent is consumed before the next call to translateKeyEvent.

**What NOT to do:**
- Do NOT modify key_encode.zig or Binding.zig -- the bug is entirely in input.zig producing wrong inputs.
- Do NOT change the modifier detection in getModifiers() -- mods reporting is correct; it's only the ToUnicode input state that needs fixing.
- Do NOT use a heap allocation for utf8 -- threadlocal static is the simplest zero-cost solution.
